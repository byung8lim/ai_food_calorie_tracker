# SQLite 데이터 모델과 마이그레이션

## 정규화 엔티티

- meals: id(문자 PK), consumed_at(ISO 날짜), meal_type, total_kcal.
- food_items: id(PK), meal_id(FK), name, category, weight_g, kcal_per_100g,
  calculated_kcal, source, confidence, bbox_json, needs_review, nutrition_source_id.
- ai_analyses: id(PK), meal_id(FK), model, raw_json, created_at.

food_items.meal_id와 ai_analyses.meal_id는 meals.id를 참조하며 삭제 시 CASCADE를
사용한다. 날짜 인덱스와 meal_id 인덱스가 있다. 각 음식별 kcal은 확정된
섭취량과 DB 열량으로 계산하고 합계는 앱에서 다시 산출한다.

## 트랜잭션과 무결성

MealStore.save는 BEGIN IMMEDIATE로 시작하여 식사·음식·분석을 저장한 뒤 COMMIT한다.
오류 시 ROLLBACK한다. SQLite FK 옵션을 켜 참조 무결성을 강제한다.

## 스키마 버전

PRAGMA user_version 0 → 1은 초기 테이블을 만들고, 1 → 2에서는
food_items.nutrition_source_id 컬럼을 없는 경우에만 추가한다.
컬럼 존재를 PRAGMA table_info로 확인하므로 여러 번 실행해도 중복 ALTER가 발생하지
않는다. 운영 반영 전 DB 백업을 받아야 한다.
