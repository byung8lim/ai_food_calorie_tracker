# AI 음식 분석 설계

## 입력과 전처리

사진은 ImagePicker로 카메라 또는 갤러리에서 받고, 이미지 라이브러리로 EXIF 방향을
정규화한 후 JPEG로 재인코딩한다. 앱은 사진마다 원본 크기와 분석용 바이트를 보유한다.
여러 사진을 순차적으로 Ollama Cloud에 전송하며, 결과 ID 앞에 사진 번호를 붙인다.
사진이 없거나 이미지 디코딩이 실패하면 API를 호출하지 않는다.

## 모델 계약

OllamaClient는 HTTPS와 API 키로 비전 모델에 요청한다. 결과는 foods 배열이어야 하며
각 항목의 ID, 이름, 분류, 중량, 신뢰도, 정규화 좌표를 AnalysisValidator가 검사한다.
좌표 값은 0에서 1 사이이고 x+width 및 y+height는 1을 초과하면 안 된다.
유효하지 않은 좌표를 생성해 채우지 않는다.

## 식사 단위 집계와 검수

사진별 결과는 후보 목록에 모은다. 같은 음식이 서로 다른 각도에서 등장할 경우
동일한 이미지 좌표계로 볼 수 없으므로 사진 간 자동 병합을 하지 않는다.
선택·수동 병합으로 중복을 없애고 각 항목에 DB 출처 또는 사용자 열량을 지정한다.
실제 음식 영역의 기하학적 분할은 ui/food_split_editor.dart가 담당한다.
분할 후 두 음식은 열량이 없는 미검수 항목으로 다시 만들어 DB 후보 선택을 요구한다.

## 에러 전략

네트워크 오류를 사용자에게 표시하고 재시도 버튼을 제공한다.
응답 스키마가 잘못되면 저장을 거부한다. 모델이 맞지 않은 음식을 높은 신뢰도로
반환할 수 있으므로 최종 확정은 사람이 수행한다.

## 잔여

분석 원본 응답의 완전한 감사 저장, 요청 취소, 여러 시점의 객체 재식별과 자동
중복 제거, 모델별 정확도 벤치마크는 아직 검증되지 않았다.
